# Super Scholar V3.2 Notes

## Purpose

V3.2 addresses the issues observed with a long-titled manuscript and a custom OpenAI-compatible gateway whose small Text / Structured / Vision tests passed while a real research-analysis request returned HTTP 554.

## Product-flow changes

- Materials automatically produce the deterministic local research profile as soon as usable parsing is complete.
- The profile page no longer asks the user to choose between a manual local button and AI. Local is the default; AI is a clearly marked recommended enhancement.
- AI still requires an explicit confirmation before any external provider request.
- Long material filenames are truncated inside a `min-w-0` content region while Ready/Server/action controls remain fixed and usable. Full names remain available through the browser title tooltip.

## AI compatibility changes

- Real research payloads use bounded retry plans rather than one all-or-nothing request.
- Retry plans progressively reduce text size, image count/resolution/detail, reasoning, output token budget and structured-output strictness. Direct PDF is disabled after the configured attempt.
- HTTP 554 and other plausible payload/provider compatibility failures are retryable; authentication/account errors are not.
- A text-only final fallback is available when text evidence exists. A single-image vision-safe final fallback is available for visual-only projects.
- Successful fallback mode and previous failures are persisted in `requestCompatibility` and shown in the profile UI.
- Exhausted retries return readable per-attempt diagnostics.

## Connection-test correction

Files API failure is optional when direct PDF sending is disabled. This matches the actual runtime path: extracted text and selected visual data URLs can use Responses/Vision without requiring `/files`.
