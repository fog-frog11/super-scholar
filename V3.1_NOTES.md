# Super Scholar V3.1 release notes

## Application-level model and OCR configuration

- Added a dedicated **模型与解析** page at `/app/settings`.
- AI settings are no longer limited to `.env`: users can select OpenAI, DeepSeek, or a custom OpenAI-compatible provider.
- Configurable provider fields: API key, Base URL, model ID, Responses/Chat Completions protocol, JSON Schema/JSON Object output, reasoning toggle/effort, vision capability, Files API capability, direct-PDF policy and analysis limits.
- Added official help links for OpenAI and DeepSeek, plus generic guidance for custom gateways.
- API keys are encrypted by the local backend with a locally generated Fernet key before SQLite persistence; the browser never receives the full saved key.
- Environment variables remain a fallback only until a UI configuration is saved.
- Added an OCR section for Tesseract executable path, OCR languages and native-text threshold, with a real local capability test.

## Provider compatibility diagnostics

`保存并测试连接` now performs staged real requests instead of treating every OpenAI-compatible endpoint as identical:

1. basic text request;
2. configured structured-output mode;
3. vision input when enabled;
4. Files API + input_file PDF round-trip when enabled.

Failures include the phase, HTTP status, upstream body snippet and request ID when available. This makes errors such as a non-standard HTTP 554 actionable instead of reducing them to a single status number.

For custom gateways the safest starting profile is JSON Object, Vision off, Files off and direct PDF off; capabilities can then be enabled one at a time after the matching test succeeds.

## Research Profile fixes

- The AI button is no longer a silent disabled control when no provider is configured. It routes to **模型与解析**, and the settings page provides a return link back to the Research Profile.
- AI analysis now accepts **visual-only projects**. A PDF containing only an image no longer fails merely because no textual evidence exists.
- If a visual-only project is used with a text-only provider and OCR produced no text, the error explicitly asks the user to enable OCR or choose a vision-capable provider.
- Provider-specific errors are preserved in the analysis run so the Research Profile shows whether failure occurred during basic provider usage, Files API upload, structured research analysis, etc.

## OpenAI / DeepSeek behavior

- OpenAI preset: `https://api.openai.com/v1`, Responses API, vision/files enabled by default.
- DeepSeek preset: `https://api.deepseek.com`, `deepseek-v4-flash`, Responses API, vision/files disabled because the current official Responses compatibility documentation does not provide image/file content to the model.
- Custom providers make no automatic `/v1`, vision or Files assumptions.
