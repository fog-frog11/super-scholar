# Super Scholar V3.3 Notes — Hierarchical AI Understanding & Cost Guards

## Why this release exists

V3.2 could send one large research payload and then perform several compatibility retries. The OpenAI Python SDK also retries selected transport/status failures by default. With a custom gateway returning a non-standard HTTP 554, those two retry layers could multiply real provider requests and cost even though the final research-analysis run failed.

V3.3 replaces that design instead of adding another retry tier.

## Request orchestration

Research understanding now uses:

```text
local material parsing
  → bounded evidence selection
  → small evidence chunks
  → one provider request per chunk
  → compact local aggregation
  → one final synthesis request
  → evidence-ID validation
```

Hard guarantees in the application code:

- OpenAI-compatible SDK client is created with `max_retries=0`.
- Each planned provider call is executed once.
- Any provider/API error stops the pipeline immediately.
- There is no automatic “compatible / compact / safe” re-send sequence.
- Raw PDFs are not uploaded by the hierarchical research-understanding pipeline.
- Per-project provider-call count is capped by `max_provider_calls`.
- Chunk extraction requests disable reasoning; configured reasoning is reserved for the final synthesis call.
- Provider errors persist safe diagnostics: phase, HTTP status, request ID, response-body preview, selected safe headers, elapsed time, input size and visual count.

## Default call budget

The UI exposes the budget in **模型与解析 → 调用预算与成本保护**.

Defaults:

- chunk text: 10,000 characters
- max real provider calls: 8, including synthesis
- visuals per chunk: 1
- chunk output: 1,800 tokens
- synthesis packet: 24,000 characters
- request timeout: 180 seconds

These limits constrain request count and payload size. They do not invent a currency cost estimate because custom providers may have different pricing/model mappings.

## HTTP 554 behavior

HTTP 554 is not a standard OpenAI API status with one universal meaning. V3.3 therefore does not guess its cause. On the first 554:

1. the current request is recorded as failed;
2. no automatic provider retry is sent;
3. the run stops;
4. the Research Profile UI shows the actual request trace and any request ID / response body / safe response headers available from the gateway.

For custom gateways, inspect the gateway's own request/channel/policy logs when a request ID is available.

## Visual-only PDFs

The visual-only PDF fix from V3.1 remains. A PDF page with no usable text can still be rendered into visual evidence and sent as a bounded visual asset when the configured provider supports vision. Text-only providers still require OCR-derived text.

## Product behavior retained

- local research profile is generated automatically;
- AI deep understanding remains an explicit recommended enhancement;
- API/OCR configuration remains in the application settings page;
- long filenames and generated evidence text remain layout-bounded;
- evidence grounding remains mandatory for AI claims;
- Compare page fixes and venue recommendation flow remain unchanged.
