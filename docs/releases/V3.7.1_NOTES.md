# Super Scholar V3.7.1 — synthesis salvage + interactive evidence

## Why this patch exists

V3.7 exposed two remaining mismatches:

1. text chunks were already salvaged item-by-item, but the final synthesis could still fall back wholesale when one grounded field (for example `stage_rationale`) contained an invalid evidence ID;
2. page-render-first visual evidence avoided PDF fragments but was still visually poor, and evidence chips did not actually navigate to their source.

## Implemented

### Final synthesis reliability

- final synthesis is parsed and validated **field by field**;
- valid AI fields are preserved; only invalid/missing fields are filled from deterministic grounded extraction;
- no repair retry is sent;
- deterministic fallback validates against **all successful extraction evidence IDs**, not only IDs that fit into the bounded final-synthesis packet;
- routine local contract normalization is reported as a collapsible note rather than a scary run-level warning;
- a truly malformed final JSON can still use full deterministic synthesis, but the run remains usable.

### Visual evidence V3

- detects Figure / Table caption lines with page coordinates;
- reconstructs composite figures from nearby vector + raster geometry;
- renders local clips with `Page.get_pixmap(..., clip=...)`;
- merges split table detections associated with one caption before rendering;
- Figure/Table crops are prioritized for Vision and the profile gallery;
- page renders are fallback/navigation assets only;
- raw embedded PDF image blocks remain trace-only.

### Interactive evidence chips

- normal UI never shows raw `ev_material_<uuid>...` IDs;
- hover tooltip shows human-readable source / filename / excerpt;
- click opens a large evidence viewer;
- PDF evidence uses an inline `/preview` route and `#page=N` navigation;
- Figure/Table evidence shows the crop and links back to the original PDF page;
- internal IDs remain available only in collapsed technical trace details.

### Coverage reporting is now honest

- the old `textCoverageRatio` was really a **raw character sampling ratio** and could
  misleadingly show values such as `19%` even when evidence from every parsed PDF page
  had entered the text-first plan;
- the request plan now reports three separate quantities:
  - `pageCoverageRatio` — parsed PDF pages touched by at least one selected evidence segment;
  - `evidenceCoverageRatio` — grounded evidence items touched by the provider plan;
  - `characterSamplingRatio` — bounded raw-text characters actually sent to the provider;
- the profile UI displays all three and explicitly explains that character sampling is
  compression, **not** page/document coverage.

### Caption compatibility

- Figure/Table caption anchors accept both Arabic and Roman numbering (`Table 2`,
  `TABLE IV`), which is common in IEEE-style computer-science papers.
