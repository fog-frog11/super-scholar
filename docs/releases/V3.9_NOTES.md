# Super Scholar V3.9.0 — Scholarly Connections + Recommendation Reliability

## Scope

V3.9 stays within the current computer-science MVP:

```text
upload research → understand research → recommend venue → compare → user selects
```

It does not add venue-style RAG, manuscript rewriting, acceptance prediction, or unauthorised JCR/WoS scraping.

## 1. Configurable scholarly data sources

A new persistent `scholarly_data_settings` record and `/api/v1/settings/scholarly` API back the **系统连接与解析 → 学术数据源** UI.

Supported sources:

- OpenAlex: semantic Works + Source identity/topics; encrypted API key; anonymous keyless mode supported but explicitly `Limited`.
- Crossref: DOI/ISSN/journal metadata; public/polite/Metadata Plus modes; encrypted Metadata Plus token when supplied.
- Semantic Scholar: independent paper/publication-venue evidence; encrypted optional API key.
- DBLP: keyless CS venue search/canonicalization.
- CCF official, CCFDDL and local References remain managed/no-key sources.

No runtime credential is bundled in the repository. Empty environment fields mean unconfigured.

## 2. Real diagnostics, not HTTP-only probes

`POST /api/v1/settings/scholarly/test` performs bounded live checks:

- OpenAlex: rate-limit/auth state → semantic Works → primary Source hydration → Source topics.
- Crossref: Works query → sample ISSN to journal resolution.
- Semantic Scholar: Academic Graph paper search.
- DBLP: venue search.

The result is stored as the last diagnostic and surfaced as `Ready`, `Limited`, `Degraded`, `Error`, or `Disabled` as appropriate.

## 3. OpenAlex Source enrichment fixed

Source hydration uses the documented `ids.openalex` filter and OR batching, with a bounded fallback to `/sources/{S...}`. `topic_share` is parsed before frequency-only `topics` when present, with deduplication by topic identity. Missing Source enrichment is not converted into a zero topic-fit score.

The deprecated OpenAlex `mailto` configuration has been removed; current authentication uses `api_key`.

## 4. Conservative venue identity

The old broad token-subset matching could make unrelated venues share the same direct publication score. V3.9 requires exact compact identity, exact acronym identity, or high overlap among distinctive venue tokens.

DBLP aliases and Crossref journal aliases are enrichment evidence only. They never manufacture a semantic fit score.

## 5. Multi-source Research Match

When evidence is available, the nominal component weights are:

- 25% OpenAlex related-paper publication-source evidence
- 25% OpenAlex Source topic fit
- 22% deterministic CS subfield scope fit
- 12% Semantic Scholar publication-venue evidence
- 12% manuscript References prior
- 4% CCF-area weak prior

Unavailable components are omitted and the remaining weights are renormalized. `null/Unknown` is distinct from a verified zero.

Research Match is a venue-fit evidence score, not an acceptance probability.

## 6. Recommendation-run health

Each run persists a `dataSourceHealth` snapshot covering:

- OpenAlex Works
- OpenAlex Sources/topics
- Semantic Scholar
- Crossref
- DBLP
- CCF journal catalog
- conference catalog / CCFDDL

The recommendation UI no longer shows an unconditional `Ready` badge. Partial connectivity is shown as `Limited`/`Degraded`, with a direct link to settings and diagnostics.

## 7. Manuscript References guardrail

Reference-community evidence is extracted only after a detected `References`/`Bibliography` heading. Publication watermarks/front matter such as “This CVPR paper…” are excluded from this signal. Generic module wording such as “three cooperative agents” is not treated as multi-agent-systems evidence.

## 8. Migration and compatibility

Alembic revision `20260829_0007` adds `scholarly_data_settings`. Existing AI provider settings, project data, material files and recommendation history remain separate.

For in-place upgrades, keep the existing `backend/data/`, `backend/storage/` and local `.env`; apply the new migration before starting the backend.
