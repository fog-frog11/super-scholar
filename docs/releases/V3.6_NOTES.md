# Super Scholar V3.6 — Text-first / Vision-separate Provider Adapters

## Problem addressed

V3.5 proved that local file parsing worked, but two provider compatibility failures remained:

1. a DeepSeek research chunk could fail even though trivial connectivity tests worked;
2. a custom OpenAI-compatible gateway behind Tencent EdgeOne could return HTTP 554 before a mixed research request completed.

Continuing to resend smaller variants of the same mixed payload would waste cost and still require every provider to implement the same multimodal protocol. V3.6 changes the architecture instead.

## New research pipeline

```text
local file parsing
→ text-only evidence chunks
→ compact grounded text facts
→ optional one-image-at-a-time visual extraction
→ compact text-only final synthesis
→ evidence validation
```

Text and images never share the same extraction request.

## DeepSeek adapter

The official DeepSeek preset now uses:

```text
deepseek-v4-pro
Chat Completions
JSON Object
SSE streaming
Vision off
Files off
```

DeepSeek Chat Completions text is serialized as a **plain string user message**, not an OpenAI-style content-part array. Thinking is explicitly disabled for extraction calls and can be enabled for synthesis.

The preset intentionally treats DeepSeek as text-only. OCR converts scanned/image material to text; users who want visual reasoning can select a vision-capable provider.

## Custom gateway Edge-safe profile

`transport_profile=auto` maps custom providers to Edge-safe:

- <= 2,800 characters per text extraction request;
- <= 700 output tokens per extraction;
- no image in text requests;
- <= 1 image request after text succeeds;
- <= 7,000-character final synthesis packet;
- synthesis reasoning disabled;
- SDK retry = 0;
- no automatic application retry.

If the first 2,800-character text-only extraction still returns a CDN/gateway error, the failure is no longer caused by PDF upload or mixed multimodal payload construction.

## Failure preservation

- Text-call failure: stop immediately.
- Optional vision-call failure after text success: keep text results and continue without additional visual calls.
- Final-synthesis failure after successful extraction: do not pay for another provider call; construct a deterministic grounded profile from the successful extracted facts and mark it `ai_extracted_partial`.

## Better error taxonomy

Diagnostics distinguish:

- `provider_transport` — HTTP/network/provider failure;
- `local_output_validation` — provider returned data but the JSON/Pydantic result was malformed or incompatible.

This removes the ambiguous “provider/local error” wording for new runs.

## Connection diagnostic

A new required `researchProbe` uses the same small text-first shape as the real extraction pipeline. It catches providers that pass a trivial JSON test but fail realistic research-JSON extraction.
